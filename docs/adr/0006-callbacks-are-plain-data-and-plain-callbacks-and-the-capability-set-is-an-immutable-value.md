# Callbacks take plain data and plain callbacks, and the capability set is an immutable value the host builds

Everything the library calls on the host is a named callback that takes and returns owned, serialisable data, plus a few plain callbacks that stand in for handles. The host registers callbacks into a builder, and the builder produces one immutable capability value that each run copies at its start. The library holds no registry. Decided 2026-11-15 in the host-interface and capability shape grilling, starting from the callback boundary recommendation agreed with the human on 2026-11-14 (issue 37, from the prototype in issue 36). It narrows ADR 0002's serialisable rule, replaces the cancel contract in ADR 0003 and the linked-token rule in ADR 0004, and answers the carries ADR 0004 and ADR 0005 left open.

## Considered options

- **A registry the library holds, with callbacks registered under a name and looked up live.** Rejected: a mid-run registration changed a run in flight, against ADR 0004, and a tool added mid-run stayed invisible to the model.
- **A held object inside a Wasm guest.** Rejected: parallel runs serialise (a 151 ms stall in the prototype); an instance per run turns it back into a value copied per run.
- **Async registration only, with a "must not block" contract.** Rejected as the only form: a blocking callback stalled its siblings and a single-thread host for its full 300 ms, and passing everything through bytes behaves the same, because the blocking question is who polls the callback, not serialisation. The contract stays documented for async callbacks.
- **Keep the cancel token with synchronous hooks and the extra poll as the contract.** Rejected: the synchronous hook does not survive the plain form and the extra poll cannot cross Wasm. Only one case failed (an inline child reporting `Aborted`, 0 of 7 across the byte and Wasm boundaries); a child the host spawns passes it everywhere.
- **A library-originated cancel (a deadline or cost cap inside the shipped loop).** Rejected for the first release: it was never exercised across the boundary, and the host can cancel with its own timer or counter.
- **A per-tool "run alone" flag.** Rejected: a host that needs ordering locks inside its callback.

## What this settles

- **Boundary.** A callback takes and returns owned, serialisable data, plus plain callbacks standing in for handles: `cancelled()`, `emit(bytes)`, and a body `read` and `close` addressed by id. A handle type (a token with hooks, a sink, a lent body stream) may exist only as an in-process Rust convenience over those; the contract never requires one. This is ADR 0002's rule with the plain callbacks added.
- **Capability kinds.** A capability is a named callback the host registers. The **tool** (a named callback with a description and a JSON schema, mapped by the codec onto the provider's tools field) is the only kind the model sees. Skills, plugins and options are not library concepts: a skill is a tool whose result is instructions, a plugin is a host bundle that registers callbacks, and settings and prompt text are plain data. The other callbacks (the model call, Transport, clock, sleeper, Offloader) are never shown to the model.
- **Registry.** The library holds none. The host registers callbacks by name into a builder, the builder produces an immutable capability value, and a run copies that value at its start and never looks a callback up again.
- **Blocking.** Two registration forms, async and blocking. A blocking callback runs on a thread the host supplies through the Offloader capability, so the gated core never blocks or starts a thread. The "blocking tool with no Offloader" check runs when the builder produces the value, so registration order does not matter. A ready-made thread pool ships only as an opt-in ungated crate, like `libharness-transport-ureq`. An uncooperative blocked thread on abort is documented, not mitigated.
- **Cancel.** Cancelling drops the callback's future, and the drop always wins. `cancelled()` is a poll-only flag for callbacks that want to clean up. The shipped loop may use an in-process token with hooks as a Rust convenience; it is not part of the contract. The library never originates a cancel in the first release: a deadline or cost cap is the host cancelling with its own timer or counter. A child run is the host's to spawn and cancel, and an inline child no longer reports `Aborted` to its parent.
- **Streaming.** The model-call callback returns the final reply. While it runs it may emit stream events through `emit(bytes)` as owned data, forwarded to the host's observer: text deltas, reasoning deltas and the core's own events. Tool calls are never emitted as fragments; they appear whole in the reply. Events are observation only, so State changes only from the final reply. A non-streaming callback never emits. Partial output on failure rides in the structured error.
- **Transport shape.** Plain data and ids. The request is method, URL, headers and body bytes; the reply is status and headers plus a body id. `body_read(id)` returns the next chunk or the end, and `body_close(id)` releases the connection (cancelling the call also closes it). Failures to reach the service (connect, TLS, timeout, closed mid-body) come back as a small structured transport error that the Exchange maps into the model-call error. In Rust, a trait with a lent `next(&mut self)` future is the in-process convenience over the ids. This answers the lent-body carry in ADR 0005.
- **Errors, retry and credentials.** A tool callback returns a plain string error, which the model reads; any retry is inside the tool. The model call returns the structured, serialisable error from issue 16 (kind, retry hint, optional partial reply, optional usage); the provider-specific fields stay with the provider abstraction grilling (issue 9). The Exchange makes one attempt. Retry is an optional helper in `libharness-loop` that takes a host-registered sleeper, is off unless one is registered, retries only when the error is retryable and nothing was delivered yet, and takes its maximum attempts from the host with no default. The library never sees or holds credentials of any kind (keys, tokens, cookies, signed URLs, client certificates, anything embedded in a URL): each Transport is built by the host and adds them, and the base URL is a plain data setting on the OpenRouter codec.
- **Tool calls in one turn.** All tool calls the model asks for in one turn start together and run concurrently; blocking ones go to the Offloader. Fan-out limits stay the host's (ADR 0004).
- **The shipped loop's surface** (`libharness-loop`). It returns the State plus an outcome saying why it stopped: answered (the typed result), turn cap reached, no answer, malformed answer after retries, cancelled by the host, or a model-call error (after any retry). The turn cap has no library default and is required, so the loop cannot be built without one. Final-answer retries default to 2 and the host can override them. The inbox is a Rust type in `libharness-loop`, not part of the callback contract. A steer is delivered at the next turn boundary, after the current tool results are absorbed and before the next model call: all queued steers go together, in order, as user messages, and a steer never interrupts a running model call or tool. A follow-up is held until the model replies asking for no more tools, then delivered as one batch and the loop continues; if the typed answer was already accepted, the loop has ended and the follow-up is not read.
- **`?Send`.** The first release is `Send` only. Callbacks and the shipped loop use boxed `Send` futures, as issue 20 decided; the pure core transitions are synchronous and do not care. A `?Send` variant for single-threaded hosts is deferred and stays fog on the map. A Wasm guest uses the core, not the loop, so it is not blocked.

## Consequences

- A blocking callback that ignores `cancelled()` keeps its thread after an abort (250 ms in the prototype, forever for a hung syscall), and a bounded Offloader stays occupied (the next blocking tool waited 360 ms with one worker). Blocking bodies should poll `cancelled()` or time out, and sizing the Offloader is the host's job.
- ADR 0004's "parent waits because its tool call is pending" still holds, but cancelling a parent no longer reaches a child automatically. The host holds the child's cancel and wires it itself.
- The prototype did not build a cooperative `op_drop` for the Wasm guest, a host-owned loop over a guest core, structured errors across the boundary (they crossed as strings), base64 bodies (raw bytes crossed), or a `?Send` variant. The cargo-deny, clippy and zero-import layers were not run on the prototype core.
- Evidence is from loopback mocks, simulated blocking and noisy timings. Nothing was run against a live service; the live smoke tests in ADR 0005 still apply.
- Retry has no timer of its own: a host that wants retry registers a sleeper or writes the retry in its own loop.
